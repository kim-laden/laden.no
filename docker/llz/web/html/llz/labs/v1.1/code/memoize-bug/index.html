Memoize Bug

Caching with a mutable key can return the wrong hit.

code algo HARD 140 XP
algo · hard · 140 XP · local flag check

Learn

Memoization stores results by key. If the key is a mutable list/dict that later changes, you get stale or colliding entries.

Lab bench

This buggy memoizer uses a list as a key:

cache = {}
def fib_key(parts):  # parts is a list
    if parts in cache: return cache[parts]
    …

What should you do to the key before inserting?

Submit flag

Hint: Never use a mutable object as a cache key — freeze/tuple it.
